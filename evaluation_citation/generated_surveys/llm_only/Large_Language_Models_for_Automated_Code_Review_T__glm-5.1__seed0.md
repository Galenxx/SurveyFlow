# 1 Abstract
Code review is a cornerstone of modern software engineering, essential for ensuring code quality, maintainability, and security. However, the manual review process is notoriously time-consuming, often creating severe bottlenecks in continuous integration pipelines and delaying software releases. The advent of Large Language Models (LLMs) has opened unprecedented avenues for automating various aspects of the code review process, including deep code understanding, review comment generation, and automated code refinement. This survey provides a comprehensive and structured overview of the application of LLMs in automated code review. We systematically categorize existing techniques into specialized pre-training, prompt engineering, and fine-tuning approaches specifically tailored for code review tasks. Furthermore, we critically examine the benchmarks and evaluation methodologies used to assess these models, highlighting the ongoing shift from traditional surface-level metrics to more nuanced, task-specific evaluations that better reflect real-world review complexities. We also explore the practical challenges and considerations of deploying these models in industrial settings, including integration with developer workflows, latency constraints, and the critical mitigation of hallucinated or incorrect outputs. Finally, we outline compelling future research directions, emphasizing the urgent need for interactive multi-turn benchmarks, repository-level contextual awareness, and secure, privacy-preserving deployment strategies. Through this survey, we aim to provide researchers and practitioners with a definitive roadmap for advancing and adopting LLM-based code review systems.

# 2 Introduction
Software development relies heavily on code review to ensure code quality, maintainability, and adherence to project standards. It serves as a critical checkpoint before code is merged into a main branch, allowing teams to share knowledge, catch subtle bugs, and enforce consistent coding practices. However, manual code review is inherently time-consuming and can create significant bottlenecks in continuous integration and deployment pipelines. Reviewers often face cognitive overload, leading to superficial reviews, delayed feedback, or review fatigue, which can ultimately compromise software reliability. To alleviate these pervasive issues, researchers and practitioners have increasingly turned to automated code review tools. While early approaches relied on static analysis and rule-based systems to detect predefined anti-patterns, the emergence of deep learning, and particularly Large Language Models (LLMs), has fundamentally revolutionized the field.

LLMs, pre-trained on vast corpora of source code and natural language text, possess a unique ability to understand complex code semantics, generate coherent natural language explanations, and even propose executable code fixes. This capability makes them exceptionally well-suited for automating the core activities of code review, such as defect detection, review comment generation, and automated code refinement. The transition from traditional machine learning models to LLMs represents a paradigm shift, moving from rigid, pattern-based anomaly detection to flexible, context-aware assistance that can adapt to the nuanced intent of the code author and the specific context of the project. Unlike their predecessors, LLMs can reason about code logic, identify security vulnerabilities, and articulate their findings in natural language, making them invaluable partners in the review process.

Despite the rapid proliferation of research in this domain, there remains a lack of a unified understanding of the current state-of-the-art, the benchmarks used for evaluation, and the practical challenges of deploying these models in real-world industrial environments. Many existing surveys focus broadly on LLMs for software engineering, without providing a granular, detailed analysis of the specific code review lifecycle and its unique demands. This survey aims to bridge this critical gap by providing a focused and comprehensive review of LLMs specifically tailored for automated code review.

The automation of code review can be decomposed into several distinct sub-tasks, each presenting its own technical hurdles. These include code review comment generation, where the model must identify potential issues and articulate them clearly; code refinement, where the model suggests specific patches to address the identified issues; and review justification, where the model explains why a certain piece of code violates best practices. LLMs have shown remarkable proficiency across these sub-tasks, often achieving performance levels that rival junior developers. However, the leap from isolated sub-task performance to seamless, end-to-end review automation requires overcoming significant integration challenges.

The scope of this survey encompasses the primary techniques employed to adapt LLMs for code review tasks, the benchmarks and metrics used to evaluate their performance, and the practical considerations for their deployment in industry. We systematically analyze the literature to identify prevailing trends, current limitations, and promising avenues for future investigation. By synthesizing these diverse aspects, we intend to provide researchers and practitioners with a clear, actionable roadmap for advancing and adopting LLM-based code review systems.

The remainder of this paper is organized as follows: Section 3 details the core techniques used for LLM-based code review; Section 4 reviews the benchmarks and evaluation methodologies; Section 5 discusses industrial deployment and integration; Section 6 highlights the challenges and open issues; Section 7 concludes the survey; and Section 8 outlines future research directions.

# 3 Techniques for Automated Code Review
The application of LLMs to automated code review encompasses a variety of techniques, ranging from specialized pre-training to prompt engineering. One prominent approach involves pre-training encoder-decoder models specifically on code review data, such as code changes and their associated review comments. For instance, models have been designed to automate code review activities by leveraging large-scale pre-training on code review trajectories, effectively capturing the complex relationship between code modifications and reviewer feedback (Li et al., 2022). Beyond general pre-training, researchers have also explored fine-tuning strategies that focus on the editing aspect of code review. Since code review often involves suggesting localized edits rather than generating entire files from scratch, models like CoditT5 have been pre-trained specifically for source code and natural language editing tasks, demonstrating superior performance in generating accurate code refinements based on review comments (Zhang et al., 2023). Furthermore, the advent of instruction-tuned LLMs has enabled the use of prompt engineering, where carefully crafted prompts guide the model to perform specific review tasks without extensive fine-tuning, allowing for rapid adaptation to diverse project-specific coding standards and guidelines.

# 4 Benchmarks and Evaluation Methodologies
Evaluating the performance of LLMs in code review requires specialized benchmarks that reflect the complexities of real-world software development. Early benchmarks primarily focused on functional correctness in code generation, utilizing test suites to validate synthesized code (Chen et al., 2021). However, code review evaluation demands more nuanced metrics that assess natural language generation quality, code refinement accuracy, and the detection of subtle semantic bugs. To address this, the community has developed polyglot benchmarks that evaluate models across multiple programming languages and diverse task formats, ensuring that automated review tools generalize well beyond a single language context (Cassano et al., 2022). Current evaluation methodologies for code review typically employ a combination of automated metrics—such as BLEU, CodeBLEU, and exact match for code refinement—and human evaluations to assess the usefulness and accuracy of generated review comments. Despite these advancements, there remains a significant gap in benchmarks that evaluate the interactive and iterative nature of code review, where a reviewer and author engage in multi-turn dialogues to reach a consensus.

# 5 Industrial Deployment and Integration
Deploying LLM-based code review systems in industrial settings introduces a unique set of challenges related to scalability, latency, and integration with existing developer workflows. A systematic understanding of how LLMs are integrated into the software development lifecycle reveals that industry adoption often favors proprietary models accessed via APIs due to their high performance, though open-source alternatives are gaining traction for data privacy reasons (Hou et al., 2023). In practice, these models are typically integrated into version control platforms as automated reviewers that provide initial feedback on pull requests, effectively reducing the manual burden on human reviewers. However, the deployment of large models requires significant computational resources, prompting the use of optimized inference techniques and distilled models to meet the strict latency requirements of continuous integration pipelines (Nijkamp et al., 2023). Furthermore, industrial deployment necessitates robust mechanisms to handle false positives and hallucinated suggestions, as irrelevant or incorrect automated comments can erode developer trust and disrupt the review process. Consequently, organizations are increasingly adopting human-in-the-loop frameworks where LLM suggestions are treated as advisory rather than authoritative.

# 6 Challenges and Open Issues
Despite the remarkable progress in LLM-based code review, several critical challenges impede their widespread and reliable adoption. One of the most pressing issues is the tendency of LLMs to hallucinate, generating plausible but factually incorrect review comments or code fixes. While reinforcement learning and specialized pre-training have been explored to improve the factual grounding of generated code, ensuring the semantic correctness of suggested refinements remains an open problem (Le et al., 2022). Additionally, LLMs often struggle with understanding the broader context of a software project, such as architectural constraints and domain-specific business logic, which are crucial for meaningful code reviews. The lack of identifier-aware reasoning in some models can lead to superficial suggestions that fail to address deeper logical flaws (Wang et al., 2021). Security and privacy concerns also pose significant challenges, as transmitting proprietary source code to third-party LLM providers risks exposing sensitive intellectual property. Finally, the inherent bias in training data can lead to inconsistent review standards, where the model disproportionately favors certain coding styles or patterns prevalent in the training corpus.

# 7 Conclusion
The integration of Large Language Models into automated code review represents a transformative shift in software engineering, offering the potential to significantly enhance developer productivity and code quality. This survey has systematically examined the current landscape of LLM-based code review, covering the spectrum from specialized pre-training techniques to the practicalities of industrial deployment. We have observed that while general-purpose LLMs demonstrate impressive zero-shot capabilities, the most effective approaches often involve domain-specific adaptation, such as pre-training on code editing tasks or fine-tuning on historical review data. These tailored models excel at generating relevant review comments and proposing accurate code refinements, thereby alleviating the cognitive load on human reviewers and accelerating the overall development lifecycle.

However, the transition from research prototypes to robust industrial tools is fraught with challenges. The evaluation of these systems remains inadequate, as existing benchmarks often fail to capture the nuanced, iterative nature of human code review. While automated metrics provide a useful proxy for measuring syntactic similarity, they are insufficient for assessing the true utility, actionability, and semantic correctness of generated feedback. In industrial settings, issues of latency, computational cost, and seamless integration with existing CI/CD pipelines are paramount. Moreover, the propensity of LLMs to hallucinate or generate superficial feedback necessitates a human-in-the-loop approach, where automated suggestions are carefully vetted by developers before implementation.

Despite these hurdles, the trajectory of the field is decidedly promising. The continuous evolution of LLM architectures, coupled with innovative training paradigms and retrieval mechanisms, is steadily addressing the limitations of current models. As the community develops more sophisticated evaluation benchmarks and deployment strategies, LLM-based code review tools are poised to become indispensable components of the modern software development toolkit. By automating the mundane and repetitive aspects of code review, these systems free developers to focus on higher-level architectural, logical, and security concerns, ultimately leading to more robust, secure, and maintainable software systems. The synergy between human expertise and artificial intelligence in code review is not merely a future vision, but an emerging reality that will continue to fundamentally shape the discipline of software engineering for years to come.

# 8 Future Directions
Looking ahead, several promising research directions are poised to advance the state-of-the-art in LLM-based automated code review. First, there is a critical need for the development of interactive and multi-turn benchmarks. Current evaluation methodologies largely treat code review as a single-shot generation task, neglecting the conversational dynamics inherent in real-world reviews. Future benchmarks should simulate the iterative dialogue between reviewers and authors, enabling the rigorous assessment of an LLM's ability to clarify suggestions, negotiate code changes, and adapt its feedback based on author responses and evolving code contexts.

Second, enhancing the contextual awareness of LLMs is essential for generating truly relevant feedback. Future models must move beyond analyzing isolated code snippets or diffs and incorporate broader repository-level context, including architectural dependencies, API usage patterns, and project-specific documentation. Retrieval-Augmented Generation (RAG) frameworks offer a promising avenue for grounding LLM responses in the specific context of a codebase, thereby reducing hallucinations and significantly improving the relevance and accuracy of review comments.

Third, the development of lightweight, domain-adapted models will be crucial for widespread industrial adoption. While massive proprietary models offer state-of-the-art performance, their computational cost and data privacy risks limit their applicability in many enterprise environments. Research into efficient model distillation, sparse attention mechanisms, and parameter-efficient fine-tuning will enable the deployment of powerful, localized code review assistants that operate seamlessly within secure, on-premise infrastructure without compromising on performance.

Fourth, the integration of multi-modal inputs presents an exciting frontier for automated code review. Code review often involves analyzing not just source code, but also system architecture diagrams, execution traces, and test outputs. LLMs capable of processing multi-modal data could provide more comprehensive and accurate feedback, identifying complex issues that are not apparent from the code text alone.

Finally, establishing robust ethical guidelines and fairness metrics for automated code review is imperative. As these systems increasingly influence development practices, it is vital to ensure they do not perpetuate biases present in historical review data or disproportionately flag code written by developers from underrepresented groups. Addressing these challenges will require interdisciplinary collaboration, ensuring that the next generation of code review tools is not only intelligent and efficient but also equitable, transparent, and trustworthy.
