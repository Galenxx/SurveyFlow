# 1 Abstract
Automated code review is a critical component of modern software development, ensuring code quality, security, and maintainability. Recently, Large Language Models (LLMs) have demonstrated remarkable capabilities in understanding and generating source code, opening new avenues for automating the code review process. This survey provides a comprehensive overview of LLMs applied to automated code review, encompassing techniques, benchmarks, and industrial deployment. We systematically categorize existing techniques into review comment generation, code refinement, and defect detection, highlighting the transition from traditional static analysis tools to deep learning and, ultimately, to LLM-based approaches. Furthermore, we examine the benchmarks used to evaluate these models, discussing their limitations and the need for more realistic, industry-aligned datasets. The deployment of LLMs in industrial settings is also analyzed, focusing on the challenges of integration, latency, and developer trust. By synthesizing current research, this survey identifies key open problems and outlines future directions, emphasizing the potential for personalized, context-aware, and autonomous code review systems. Ultimately, we aim to provide researchers and practitioners with a structured understanding of how LLMs are reshaping the landscape of automated code review.

# 2 Introduction
Code review is a fundamental software engineering practice where developers critically examine source code written by their peers to identify defects, improve readability, and ensure adherence to project standards. Historically, this process has been manual, requiring significant human effort and time, which often creates bottlenecks in continuous integration and deployment pipelines. As software systems grow in size and complexity, the volume of code requiring review has increased exponentially, making purely manual review unsustainable. Consequently, the software engineering community has sought automated solutions to alleviate the burden on developers. Early automated code review tools relied on static analysis and heuristic rule-based methods. While effective for enforcing style guidelines and detecting common anti-patterns, these tools often produce high false-positive rates and lack the deep semantic understanding required to evaluate complex logic or generate constructive feedback.

The advent of deep learning, particularly the emergence of Large Language Models (LLMs), has revolutionized the field of automated code review. Trained on vast repositories of open-source code, LLMs possess an unprecedented ability to comprehend code semantics, natural language instructions, and the intricate patterns underlying software development. Unlike their predecessors, LLMs can generate human-like review comments, automatically suggest code fixes, and even detect subtle vulnerabilities that evade traditional static analyzers. This paradigm shift has sparked a surge of research exploring the application of LLMs across various stages of the code review lifecycle, from pre-commit checks to automated patch generation.

Modern code review is not a monolithic activity but rather a collection of interconnected sub-tasks. These include understanding the intent of the code author, identifying potential functional bugs or security vulnerabilities, suggesting alternative implementations, and verifying that the proposed changes align with the broader system architecture. LLMs are uniquely positioned to address these sub-tasks due to their dual proficiency in both programming languages and natural language. By leveraging the in-context learning capabilities of state-of-the-art models, developers can now receive instantaneous, context-aware feedback on their contributions. However, the transition from research prototypes to production-ready systems requires navigating a complex landscape of technical and organizational constraints.

Despite the rapid progress, the landscape of LLM-based code review remains fragmented. Researchers and practitioners face challenges in understanding the capabilities and limitations of different modeling approaches, the adequacy of current evaluation benchmarks, and the practical hurdles of deploying these models in real-world industrial environments. Existing surveys often focus broadly on LLMs for software engineering, lacking a dedicated, in-depth analysis of the code review domain. This survey aims to bridge this gap by providing a focused and comprehensive review of LLMs specifically tailored for automated code review.

The scope of this survey encompasses the core techniques employed in LLM-driven code review, the benchmarks designed to evaluate their performance, and the practical considerations for their industrial deployment. We systematically analyze how LLMs are fine-tuned or prompted for tasks such as review comment generation, code refinement, and defect detection. We also critically assess the datasets and metrics used to benchmark these models, highlighting the disconnect between academic evaluation and industrial requirements. Finally, we explore the challenges and strategies associated with integrating LLMs into developer workflows, addressing issues such as latency, explainability, and user trust. The structure of this paper is as follows: Section 3 discusses the core techniques and model architectures. Section 4 examines the benchmarks and evaluation methodologies. Section 5 delves into the practical aspects of industrial deployment. Section 6 highlights the limitations and challenges of current approaches. # 3 Techniques and Model Architectures
The application of Large Language Models to automated code review relies on sophisticated architectures and training methodologies adapted from natural language processing. Early approaches utilized sequence-to-sequence models, but the field has rapidly adopted large-scale pre-trained transformers. The core techniques for code review are generally divided into three primary tasks: review comment generation, code refinement (or automated code repair), and defect detection.

For review comment generation, models are trained to translate a code diff into a natural language critique. This requires the model to understand not just the syntax, but the intent of the code change. Pioneering work in this area, such as CodeReviewer, introduced pre-training objectives specifically designed for code review activities, demonstrating that task-aware pre-training significantly outperforms general-purpose models (Li et al., 2022). Similarly, sequence editing models like CoditT5 have been proposed to handle the inherent structure of code diffs, treating code changes as edits rather than generation from scratch (Li et al., 2022). 

Code refinement, the task of automatically fixing code based on review feedback, essentially inverts the comment generation task. Here, the model takes the original code and the review comment as input and outputs the revised code. State-of-the-art LLMs approach this using instruction tuning and reinforcement learning from human feedback to align the generated patches with developer intent. Defect detection, on the other hand, leverages the LLM's deep semantic understanding to identify vulnerabilities and bugs. By framing defect detection as a code comprehension task, LLMs can recognize complex vulnerability patterns that traditional static analysis tools miss. The shift from encoder-only models to encoder-decoder and decoder-only models has enabled a unified approach where a single model can be prompted to perform all these tasks, albeit with varying degrees of success depending on the model's parameter count and fine-tuning strategy.

# 4 Benchmarks and Evaluation Methodologies
Evaluating the performance of LLMs in automated code review requires robust benchmarks that accurately reflect real-world review scenarios. Historically, the field has relied on datasets extracted from open-source platforms like GitHub and Gerrit. The most prominent benchmark for review comment generation and code refinement is constructed from massive historical code changes, where the input is the code diff and the target is the reviewer's comment or the subsequent code patch.

However, current evaluation methodologies face significant limitations. The standard metrics for assessing review comment generation are primarily BLEU and ROUGE, which measure n-gram overlap between the generated comment and the reference comment. These lexical metrics are fundamentally inadequate for code review, as multiple semantically equivalent comments can have entirely different lexical compositions. A review comment stating "This loop is inefficient" and another saying "Consider using a hash map instead of a nested loop" might be equally valid, yet lexical metrics would assign them a low similarity score.

To address these shortcomings, recent research has advocated for the use of LLMs themselves as evaluators, employing LLM-as-a-judge frameworks to assess the semantic correctness and relevance of generated review comments. Furthermore, benchmarks for code generation, such as HumanEval, have been adapted to evaluate the code refinement capabilities of LLMs (Chen et al., 2021). Yet, a critical gap remains between these academic benchmarks and the complexity of industrial code reviews, which involve massive context windows, multi-file dependencies, and project-specific conventions. The development of context-rich, repository-level benchmarks is essential for accurately gauging the efficacy of LLMs in realistic code review settings (Hou et al., 2023).

# 5 Industrial Deployment and Integration
Deploying LLMs for automated code review in industrial environments introduces a myriad of practical challenges that are often abstracted away in academic research. While models may perform exceptionally well on curated benchmarks, integrating them into the continuous integration/continuous deployment (CI/CD) pipelines of large software organizations requires careful consideration of latency, scalability, and developer experience.

One of the primary hurdles is inference latency. Code reviews are time-sensitive, and developers expect feedback within seconds. Running billion-parameter LLMs locally or via cloud APIs can introduce unacceptable delays, particularly when analyzing large code diffs. Organizations must navigate the trade-off between model accuracy and inference speed, often opting for smaller, distilled models or quantization techniques to meet service-level agreements.

Another critical aspect is developer trust and adoption. Automated review tools are notorious for high false-positive rates, which can lead to "alert fatigue" and cause developers to ignore the automated feedback entirely. For LLMs to be effectively adopted, their outputs must be not only accurate but also explainable. Providing the rationale behind a suggested code change or a review comment is crucial for building trust. Furthermore, industrial deployment requires strict data privacy and security measures. Proprietary source code cannot be sent to public LLM APIs, necessitating the use of on-premise deployments or secure, isolated environments. The rise of open-source models tailored for code, such as Code Llama, has facilitated on-premise deployments, allowing companies to fine-tune models on their internal codebases while retaining complete control over their intellectual property (Roziere et al., 2023). Effective integration also involves seamlessly embedding the LLM into existing developer tools and IDEs, ensuring that the AI acts as a collaborative assistant rather than a disruptive barrier (Fan et al., 2023).

# 6 Limitations and Challenges
Despite the remarkable advancements in LLM-driven code review, several profound limitations and challenges persist. A fundamental issue is the tendency of LLMs to hallucinate, generating plausible but factually incorrect review comments or code patches. In the context of code review, a hallucinated suggestion can be highly detrimental, potentially introducing new bugs or security vulnerabilities if a developer blindly accepts the recommendation.

Context limitation is another significant challenge. Code review is inherently a repository-level task; understanding the impact of a code change often requires analyzing multiple files, classes, and dependencies. However, most LLMs are constrained by finite context windows, making it difficult to process large pull requests or incorporate the broader project context. While techniques like retrieval-augmented generation (RAG) can help inject relevant context, they add complexity and can still miss implicit project knowledge.

Furthermore, current LLMs struggle with complex logical reasoning. While they excel at identifying surface-level issues such as style violations or missing error checks, they often fail to detect deep, algorithmic flaws or complex concurrency issues. The quality of the training data also poses a challenge; models trained on open-source code may learn suboptimal practices or reinforce existing biases present in the data (Zhang et al., 2023). Finally, the evaluation of LLMs for code review remains inadequate, as automated metrics fail to capture the nuanced, subjective nature of code quality. Overcoming these limitations requires moving beyond scaling up models, focusing instead on improving reasoning capabilities, context management, and the development of robust, human-centric evaluation frameworks.

# 7 Conclusion
The integration of Large Language Models into automated code review represents a transformative shift in software engineering. This survey has systematically examined the current state of LLMs applied to code review, detailing the evolution from traditional static analysis to advanced, deep learning-driven techniques. We categorized the primary tasks in this domain—review comment generation, code refinement, and defect detection—and highlighted the architectural innovations, such as task-specific pre-training and instruction tuning, that have propelled the field forward.

Our analysis of benchmarks and evaluation methodologies reveals a critical disconnect between academic progress and industrial reality. While existing datasets have been instrumental in driving initial research, their reliance on lexical metrics like BLEU and ROUGE fails to capture the semantic nuances of effective code review. The push toward LLM-as-a-judge and repository-level benchmarks is a necessary step toward more meaningful evaluation, but further work is required to align these benchmarks with the complex, multi-file contexts typical of industrial software development.

The deployment of LLMs in industry underscores the practical challenges of adopting generative AI in software pipelines. Issues of latency, data privacy, and developer trust are paramount. The success of these systems hinges not just on the accuracy of the models, but on their ability to provide explainable, actionable feedback that developers can seamlessly integrate into their workflows. The emergence of powerful open-source models has begun to alleviate privacy concerns, enabling on-premise deployments that safeguard proprietary code.

Ultimately, while LLMs are not yet capable of fully replacing human reviewers, they serve as powerful assistants that can automate the tedious aspects of code review, allowing developers to focus on higher-level architectural and logical concerns. The journey toward fully autonomous code review is ongoing, and addressing the current limitations regarding hallucinations, context windows, and complex reasoning will dictate the pace of future advancements.

# 8 Future Directions
As the field of LLM-based automated code review matures, several promising research directions emerge. First, the development of repository-level and organization-aware code review systems is crucial. Future models must move beyond analyzing isolated code diffs and instead understand the entire codebase, including its architecture, dependency graph, and project-specific conventions. Fine-tuning LLMs on internal codebases and style guides will enable highly personalized review experiences that align with organizational standards.

Second, improving the reasoning capabilities of LLMs is essential for detecting complex logical and security vulnerabilities. Current models often rely on pattern matching rather than deep logical deduction. Integrating formal methods or neuro-symbolic approaches with LLMs could enhance their ability to verify code correctness and identify subtle concurrency or memory safety issues, bridging the gap between static analysis and generative AI.

Third, the concept of autonomous code review agents presents a compelling frontier. Rather than passively generating comments, future systems could act as interactive agents that engage in a dialogue with the developer, propose fixes, automatically run test suites to verify the patches, and iteratively refine their suggestions based on feedback. This agentic workflow would significantly reduce the manual effort required in the review cycle.

Fourth, there is an urgent need for robust, human-centric evaluation frameworks. Moving beyond automated metrics, the community must establish standardized protocols for human evaluation that assess the actionability, relevance, and security of LLM-generated review feedback. Additionally, research into the explainability of LLM suggestions will be vital for fostering developer trust and facilitating the debugging of model errors.

Finally, addressing the ethical and security implications of LLMs in code review is paramount. Defending against prompt injection attacks, ensuring that models do not leak sensitive information, and mitigating biases in code suggestions are critical areas of research. By tackling these challenges, the community can pave the way for the next generation of intelligent, secure, and reliable automated code review systems.
