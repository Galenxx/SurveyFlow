# 1 Abstract
Automated code review is a cornerstone of modern software development, ensuring code quality, security, and maintainability. Recently, Large Language Models (LLMs) have emerged as powerful tools for automating various code review tasks, including defect detection, review comment generation, and code refinement. This survey provides a comprehensive overview of the application of LLMs in automated code review, covering the key techniques, benchmarks, and challenges associated with industrial deployment. We begin by categorizing the primary techniques employed, ranging from early encoder-decoder models to advanced large-scale decoder-only architectures and instruction-tuned LLMs, highlighting how these approaches address specific review activities like comment generation and code repair. Next, we examine the benchmarks and datasets used to evaluate these models, discussing their limitations and the critical need for more realistic, industry-aligned evaluation frameworks that capture the nuanced nature of human review. Furthermore, we explore the practical challenges of deploying LLMs in industrial settings, such as seamless integration with existing developer workflows, latency constraints, data privacy concerns, and the mitigation of hallucinations. By synthesizing current research, this survey aims to provide researchers and practitioners with a structured understanding of the landscape, identifying the persistent gaps between academic benchmarks and industrial needs, and outlining promising directions for future exploration in the era of LLM-driven software engineering.

# 2 Introduction
Modern software development heavily relies on code review as a critical quality assurance mechanism. In contemporary workflows, such as those centered around GitHub pull requests or Gerrit, developers submit code changes that must be scrutinized by their peers before integration. While this practice, known as Modern Code Review (MCR), is indispensable for maintaining code quality, identifying security vulnerabilities, and sharing knowledge across teams, it is inherently time-consuming and often constitutes a significant bottleneck in the software development lifecycle. Reviewers frequently face cognitive overload, leading to delayed feedback, review fatigue, or superficial inspections. Consequently, the software engineering community has long sought to automate or assist the code review process to alleviate this burden.

Traditionally, automated code analysis was dominated by static analysis tools and linters, which, while effective at enforcing style guidelines and detecting well-known anti-patterns, lack the semantic understanding required to provide high-level architectural feedback or context-specific suggestions. The advent of deep learning introduced initial forays into automated code review, primarily relying on recurrent neural networks or early sequence-to-sequence models. However, these approaches were severely limited by their inability to capture deep semantic understanding and long-range dependencies inherent in source code and natural language.

The emergence of Large Language Models (LLMs) has fundamentally transformed this landscape. Pre-trained on massive corpora of source code and natural language text, LLMs exhibit remarkable proficiency in understanding code semantics, generating natural language comments, and even refining code based on natural language instructions. This paradigm shift has enabled the automation of complex review activities—such as generating review comments, localizing defects, and automatically suggesting code patches—that were previously considered the exclusive domain of human experts. By leveraging the dual modalities of natural language and programming languages, LLMs can bridge the gap between code intent and implementation.

Despite the rapid proliferation of research in this domain, there remains a lack of a unified understanding of the current state, capabilities, and limitations of LLMs for automated code review. Academic benchmarks often fail to reflect the complexities of industrial deployments, where factors such as repository-specific context, latency constraints, data privacy, and integration friction play decisive roles. Furthermore, the tendency of LLMs to hallucinate plausible but incorrect suggestions poses a significant risk in safety-critical software systems. This survey seeks to bridge the gap between academic innovation and industrial application by providing a comprehensive and structured analysis of LLM-driven code review.

The scope of this survey encompasses the core code review activities that LLMs target: review comment generation, code defect detection, and automated code refinement. We systematically examine the architectural evolution of models tailored for these tasks, the benchmarks used to evaluate them, and the practical considerations for deploying them in real-world environments.

The structure of this survey is as follows. Section 3 delves into the techniques and architectures employed, tracing the evolution from early pre-trained models to state-of-the-art LLMs. Section 4 surveys the benchmarks and datasets that underpin model evaluation, highlighting their strengths and shortcomings. Section 5 discusses the realities of industrial deployment, focusing on integration and operational challenges. Section 6 examines the overarching challenges, including hallucination and evaluation validity. Finally, Section 7 provides concluding remarks, and Section 8 outlines promising future directions for the field.

# 3 Techniques and Architectures for Code Review
The application of LLMs to automated code review has evolved significantly, driven by advances in model architectures and pre-training objectives. Early approaches leveraged encoder-only models to capture code semantics for classification tasks such as defect detection. However, the need to generate natural language comments and modified code sequences spurred the adoption of encoder-decoder architectures. A foundational work in this space is CodeReviewer, which introduced pre-training tasks specifically designed for code review, such as code difference generation and review comment generation (Li et al., 2022). These task-specific pre-training strategies allowed models to learn the nuanced relationship between code changes and human feedback, establishing a strong baseline for generative review tasks.

More recently, the field has shifted towards large-scale decoder-only models, such as those in the LLaMA and Code Llama families, which leverage instruction tuning to perform a wide array of software engineering tasks. These models excel in zero-shot and few-shot scenarios, enabling them to generate review comments or refine code without requiring extensive task-specific fine-tuning. The shift from specialized pre-training to general-purpose instruction following represents a significant paradigm shift, allowing a single model to handle diverse review activities—from identifying security vulnerabilities to suggesting refactoring strategies—through carefully crafted prompts. This flexibility has made decoder-only LLMs the dominant architecture in contemporary automated code review research.

# 4 Benchmarks and Evaluation Methodologies
The evaluation of LLMs for code review heavily relies on curated benchmarks derived from open-source software repositories. The most prominent datasets, such as those constructed from GitHub pull requests, provide pairs of code diffs, review comments, and refined code. These benchmarks enable the quantitative evaluation of tasks like review comment generation and code refinement using standard natural language processing metrics such as BLEU, ROUGE, and CodeBLEU.

However, current evaluation methodologies face significant limitations. Traditional string-matching metrics often fail to capture the semantic correctness and actionable nature of review comments. A comment that is lexically similar to the reference but functionally misleading may score highly, while a semantically equivalent but lexically distinct comment may be penalized. Furthermore, comprehensive surveys highlight that existing benchmarks often lack the contextual richness of real-world reviews, omitting lengthy conversation histories, repository-specific guidelines, and multi-file dependencies (Hou et al., 2023). Consequently, there is a growing consensus that automated metrics must be supplemented with human evaluations or LLM-as-a-judge frameworks to accurately assess the practical utility and factual accuracy of automated code review systems.

# 5 Industrial Deployment and Integration
Transitioning LLM-based code review tools from research prototypes to industrial deployment introduces a myriad of practical challenges. In industry, code review is not merely a defect detection exercise but a collaborative process deeply integrated into developer workflows via platforms like GitHub, GitLab, and Bitbucket. For an LLM to be adopted, it must seamlessly integrate into these platforms, providing timely and non-intrusive suggestions.

One of the primary hurdles is inference latency. In a fast-paced development environment, reviewers expect feedback within seconds. Deploying massive, billion-parameter models can violate these latency constraints, necessitating the use of smaller, distilled models or optimized serving infrastructure. Additionally, data privacy is a paramount concern. Proprietary codebases cannot be sent to third-party LLM APIs, forcing organizations to deploy open-source models locally or on private clouds. The release of open foundation models has significantly alleviated this issue, providing performant baselines that can be fine-tuned on proprietary data without compromising intellectual property (Roziere et al., 2023). Furthermore, industrial deployments must carefully manage the signal-to-noise ratio; overwhelming developers with irrelevant or incorrect suggestions leads to "alert fatigue," ultimately causing the automated review tool to be ignored or disabled.

# 6 Challenges and Limitations
Despite their impressive capabilities, LLMs for code review suffer from several critical limitations. The most prominent issue is hallucination, where the model generates plausible but factually incorrect review comments or code patches. In the context of code review, a hallucinated suggestion can mislead developers, introduce new bugs, or waste valuable engineering time. Addressing this requires robust grounding mechanisms and confidence calibration.

Another significant challenge is the limited context window of current models. Effective code review often requires understanding the broader repository context, including architectural decisions, dependencies, and historical changes, which can span thousands of tokens. While techniques like retrieval-augmented generation (RAG) offer partial solutions, they struggle with complex cross-file dependencies. Furthermore, the evaluation of automated program repair and code refinement remains challenging, as multiple semantically equivalent patches may exist for a given issue, yet strict metrics may fail to recognize them (Xia et al., 2023). Overcoming these limitations requires advancements in long-context modeling, rigorous evaluation frameworks, and techniques to minimize hallucinations in safety-critical applications.

# 7 Conclusion
The integration of Large Language Models into automated code review represents a significant paradigm shift in software engineering. This survey has traversed the landscape of LLM-driven code review, examining the evolution of techniques, the state of benchmarks, and the realities of industrial deployment. From the early adoption of encoder-decoder models specifically pre-trained for review tasks, such as comment generation and code refinement, to the current dominance of massive, instruction-tuned decoder-only models, the technical trajectory is clear. The field is moving rapidly towards generalist models capable of handling diverse review activities through prompt engineering and lightweight fine-tuning, rather than training specialized models from scratch.

We have highlighted that while LLMs demonstrate remarkable proficiency in generating natural language feedback and suggesting code modifications, their practical utility is heavily constrained by evaluation methodologies that fail to capture the semantic nuances of human review. Existing benchmarks, though useful for tracking quantitative progress, often strip away the rich contextual and conversational elements that characterize real-world code review. This leads to a persistent disconnect between benchmark performance and industrial efficacy, as models that excel on static datasets may struggle in dynamic, repository-level environments.

Furthermore, the deployment of these models in industrial settings remains fraught with practical challenges. Issues of inference latency, data privacy, and the critical need to avoid developer alert fatigue through high-precision suggestions are paramount for adoption. The availability of open-source foundation models has empowered organizations to leverage LLMs internally without compromising proprietary code, yet the risk of hallucinations—where models generate plausible but misleading feedback—continues to necessitate human oversight. The ultimate goal of current LLM-based review systems is not to replace human reviewers but to augment them, acting as a tireless first pass that catches common defects and suggests potential improvements.

As the technology matures, the success of LLM-based code review hinges on bridging the gap between academic research and industrial practice. By focusing on context-aware modeling and developing evaluation metrics aligned with developer productivity, LLMs are poised to become an indispensable component of the modern software development lifecycle, transforming code review from a frequent bottleneck into a streamlined, intelligent, and collaborative process.

# 8 Future Directions
As the field of LLM-based automated code review continues to mature, several promising research directions emerge. First, there is an urgent need for repository-level and organization-level customization. Current models are typically pre-trained on general open-source data, which may not align with the specific coding standards, architectural patterns, or domain-specific requirements of a particular organization. Future research should focus on efficient adaptation techniques, such as parameter-efficient fine-tuning (PEFT) and retrieval-augmented generation (RAG), that allow models to dynamically incorporate organizational knowledge bases, style guides, and historical review data without prohibitive computational costs.

Second, the development of multi-modal and interactive review systems represents a critical frontier. Code review is inherently interactive, often involving multiple rounds of dialogue between the author and the reviewer. Future LLMs should be capable of engaging in multi-turn conversations, asking clarifying questions, and updating their suggestions based on developer feedback. Moving beyond single-pass generation towards agentic workflows—where LLMs can execute code, run tests, and verify their own suggestions—will significantly enhance the reliability and actionability of automated reviews.

Third, advancing evaluation methodologies is essential. The field must move beyond traditional string-matching metrics towards functional and semantic evaluation. This includes the development of automated test suites to verify the correctness of generated code patches, as well as large-scale, standardized human evaluation frameworks that assess the true utility of review comments in practice. LLM-as-a-judge frameworks, where advanced models evaluate the output of other models, also offer a scalable alternative to human evaluation, though they require careful calibration to avoid inherent biases.

Finally, addressing the security and safety of LLM-driven code review is paramount. As these models become more integrated into CI/CD pipelines, they become attractive targets for adversarial attacks. Research into adversarial robustness, data poisoning prevention, and the detection of malicious code suggestions will be crucial to ensuring that automated code review systems enhance, rather than compromise, software security. By pursuing these directions, the community can unlock the full potential of LLMs to revolutionize code review.
