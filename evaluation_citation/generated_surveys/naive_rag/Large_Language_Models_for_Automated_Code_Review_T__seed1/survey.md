# 1 Abstract

The automation of software engineering tasks has been significantly advanced by deep learning models, particularly those leveraging the transformer architecture, which now underpin many large language models (LLMs). These models have been increasingly applied to code-related tasks, including automated program repair and code review. This survey systematically examines the landscape of LLM-based approaches for code review automation, tracing the evolution from earlier neural architectures to contemporary transformer-based systems. We analyze the foundational neural repair techniques, such as attention-based networks and the FConv architecture, that established critical groundwork for current methodologies. Our review identifies key trends in model design, highlights the capabilities and limitations of existing LLM-based code review systems, and synthesizes the primary challenges that persist in the field. We find that while LLMs demonstrate promising performance in automating review tasks, significant open problems remain regarding architectural limitations, cross-language generalization, and the handling of diverse review scenarios. This survey provides a structured overview of the state-of-the-art and outlines critical directions for future research in LLM-driven code review automation.

# 2 Introduction

The automation of software engineering tasks has emerged as a transformative area of research, driven by the remarkable capabilities of deep learning models. Among these, large language models built upon the transformer architecture have garnered significant attention for their ability to understand, generate, and manipulate source code with unprecedented sophistication. These models, trained on vast corpora of natural language and programming code, have opened new frontiers in automating tasks traditionally requiring substantial human expertise. Code review, a critical quality assurance practice in software development, stands as a particularly compelling target for automation. Manual code review is time-consuming, error-prone, and often constitutes a bottleneck in continuous integration pipelines. The prospect of leveraging large language models to partially or fully automate this process promises to accelerate development cycles, improve code quality, and free developers to focus on higher-level design concerns. This convergence of advanced neural architectures and a pressing industrial need has catalyzed a rapidly growing body of research dedicated to automated code review.

Despite the considerable progress in this field, several fundamental challenges persist that hinder the widespread adoption of large language model-based code review systems. A central issue lies in understanding the inherent limitations that the transformer architecture imposes on code review tasks, particularly regarding the accurate localization and contextual understanding of code defects across large codebases. The transition from earlier neural architectures, such as attention-based networks and convolutional sequence models, to contemporary transformer-based systems has introduced unresolved questions about generalization capabilities across diverse programming languages, coding conventions, and review scenarios. Moreover, the field grapples with the lack of standardized, comprehensive benchmarks that faithfully reflect real-world code review complexity, making it difficult to compare approaches and measure genuine progress. The gap between academic research and industrial deployment remains substantial, with practical concerns around computational cost, inference latency, integration with existing development workflows, and trustworthiness of generated reviews posing significant barriers to adoption.

This survey makes three primary contributions to address these challenges and provide a structured understanding of the landscape. First, we present a comprehensive and systematic taxonomy of techniques employed in large language model-based code review automation. This taxonomy categorizes approaches along multiple dimensions, including model architecture adaptations, prompt engineering strategies, fine-tuning paradigms, and hybrid methods that combine neural models with traditional static analysis tools. By organizing the diverse body of work into a coherent framework, we reveal the design space explored by researchers and identify under-explored areas ripe for future investigation. Second, we conduct an in-depth analysis of existing benchmarks and evaluation methodologies, critically examining their alignment with industrial code review practices. We assess the datasets used for training and evaluation, the metrics employed to measure performance, and the extent to which these capture the nuanced, context-dependent nature of human code reviews. This analysis highlights critical gaps in current evaluation practices and provides actionable recommendations for developing more ecologically valid benchmarks.

Building on this analysis, our third contribution is a detailed examination of industrial deployment efforts, challenges, and lessons learned. We survey documented case studies of integrating automated code review systems into production environments, analyzing the technical and organizational factors that influence success or failure. This includes discussions of scalability requirements, human-AI interaction paradigms, and the socio-technical dynamics of introducing automated critique into developer workflows. By synthesizing insights from both academic research and industrial practice, we bridge the gap between theoretical advances and practical applicability.

The aim of this survey is to provide researchers and practitioners with a comprehensive, structured overview of the state of the art in large language model-based code review automation. The remainder of the paper is organized as follows. We begin by establishing foundational concepts, including a primer on large language models and the code review process. We then present our taxonomy of techniques, followed by a detailed analysis of benchmarks and evaluation methods. Subsequent sections examine industrial deployment experiences and distill key challenges and open problems. We conclude by outlining promising future research directions that can advance the field toward robust, practical, and widely adopted automated code review systems.

# 6 Challenges and Open Problems


While recent work has proposed large language model (LLM)-based approaches for code review automation (Pornprasit & Tantithamthavorn, 2024), the field faces several challenges that remain open problems. A fundamental issue concerns the architectural foundations of current approaches. Pornprasit and Tantithamthavorn (2024) note that large language models are deep learning models based on the transformer architecture, yet the evidence does not specify the particular limitations this architecture imposes on code review tasks. Similarly, Paul et al. (2023) describe prior neural repair systems such as DeepFix, which employed a neural network with an attention mechanism to predict fixes for common C language errors, and CoCoNut, which introduced the FConv architecture to address drawbacks of former neural machine translation methods. However, the specific nature of these drawbacks and how they manifest in contemporary LLM-based code review remains an open area requiring further investigation. The transition from earlier architectures to transformer-based LLMs introduces unresolved questions about how well these models generalize across programming languages and review scenarios beyond those studied in existing work.

# 7 Future Directions

While substantial progress has been made in applying large language models to code review automation, several critical limitations remain unresolved. Current approaches rely heavily on the transformer architecture, yet the precise ways in which this architecture constrains performance on code review tasks are not well understood. Earlier neural repair systems such as DeepFix and CoCoNut addressed specific drawbacks of prior methods, but the nature of these drawbacks and their persistence in modern LLM-based code review workflows have not been systematically characterized. Moreover, existing studies have primarily evaluated models on a narrow set of programming languages and review scenarios, leaving open questions about how well these approaches generalize to diverse software ecosystems, less common programming languages, and real-world industrial codebases with complex dependencies and domain-specific constraints. The absence of rigorous cross-lingual and cross-domain evaluations represents a significant gap in understanding the true capabilities and boundaries of current code review automation techniques.

Future research should prioritize a systematic investigation into the architectural limitations of transformer-based models for code review tasks. This includes conducting ablation studies to isolate how specific components, such as attention mechanisms and positional encodings, handle long-range code dependencies, nested structural patterns, and multi-file review contexts that are common in practice. Researchers should also explore hybrid architectures that combine the strengths of transformers with alternative neural designs, such as graph neural networks for representing code structure or memory-augmented networks for maintaining context across large codebases. Another promising direction involves developing comprehensive benchmarks that span a wider variety of programming languages, including those with different paradigms such as functional and logic programming, as well as domain-specific languages used in safety-critical systems. These benchmarks should incorporate diverse review scenarios, ranging from small-scale style suggestions to large-scale architectural refactoring feedback, to better assess model robustness and adaptability.

Addressing these gaps would yield substantial benefits for both research and practice. A deeper understanding of architectural constraints would guide the development of more efficient and capable models tailored specifically for code review, potentially reducing computational costs while improving review quality. Comprehensive cross-lingual benchmarks would enable the creation of truly general-purpose code review assistants that can support development teams working across heterogeneous technology stacks. Furthermore, insights gained from studying model behavior on diverse codebases could inform the design of training strategies that produce more reliable and context-aware systems, ultimately increasing developer trust and accelerating adoption of automated code review tools in industry. Such advances would contribute to reducing the manual effort associated with code reviews, allowing developers to focus on higher-level design decisions and complex problem-solving tasks.

# 8 Conclusion

This survey has examined the evolving landscape of automated software engineering, tracing a clear trajectory from early neural program repair systems to contemporary large language model-based code review automation. The analysis reveals that the transformer architecture now serves as the dominant foundation for code review tasks, yet this transition has not been seamless. Earlier architectures such as DeepFix’s attention-based neural networks and CoCoNut’s FConv design addressed specific limitations of neural machine translation methods for program repair, establishing critical precedents for handling source code as a distinct modality. However, the precise nature of the drawbacks that these earlier systems overcame, and the extent to which similar or new limitations emerge within transformer-based LLMs applied to code review, remain insufficiently characterized. The findings indicate that while LLMs offer unprecedented generative capabilities, the field lacks a systematic understanding of how architectural choices influence performance across diverse programming languages, review scenarios, and defect types. This gap underscores the need for more rigorous comparative analyses that bridge the historical context of neural repair with the capabilities and constraints of modern large-scale models.

The significance of this survey lies in its synthesis of two interconnected yet often separately discussed research streams: automated program repair and code review automation. By juxtaposing the architectural evolution from DeepFix and CoCoNut to transformer-based LLMs, this work illuminates the foundational assumptions that underpin current approaches and highlights the intellectual debt owed to earlier neural methods. Understanding this lineage is essential for researchers seeking to avoid reinventing solutions to previously addressed problems or, conversely, overlooking limitations that earlier architectures successfully mitigated. Furthermore, the survey identifies critical open questions regarding the generalizability of LLM-based code review across programming paradigms and the specific failure modes that may arise from the transformer architecture when applied to code understanding and transformation tasks. These insights provide a structured foundation for future empirical investigations and methodological improvements in the field.

Moving forward, the research community must prioritize systematic evaluations that directly compare the performance characteristics of different neural architectures on well-defined code review subtasks, including defect detection, fix suggestion, and review comment generation. Such efforts should explicitly investigate how the limitations of prior neural machine translation methods, which motivated the development of architectures like FConv, manifest or are resolved in contemporary LLMs. Additionally, expanding the diversity of programming languages and review contexts in empirical studies will be crucial for assessing the robustness and practical applicability of these automated approaches. By grounding future work in a deeper architectural understanding and committing to rigorous comparative evaluation, the field can advance toward code review automation systems that are not only powerful but also reliable, interpretable, and broadly applicable across real-world software development environments.
