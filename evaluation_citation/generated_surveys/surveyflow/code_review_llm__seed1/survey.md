# 1 Abstract

The automation of code review and program repair has become a critical area in software engineering, driven by the increasing capabilities of large language models to understand and generate source code. This survey provides a structured overview of recent advances in automated program repair and code review, examining the roles of fine-tuned models, prompt engineering, and multi-agent frameworks in addressing bug detection and correction. We analyze the dominant paradigm of full fine-tuning, where models such as CodeT5 and PLBART are adapted for sequence-to-sequence repair tasks, and contrast this with emerging trends toward parameter-efficient specialization and role-specific agent tuning within cooperative architectures. The review further investigates the integration of code review signals as a refinement mechanism, the iterative test-and-fix loops enabled by prompt-driven debugging, and the critical challenges in evaluating generated code quality, including the documented disconnect between surface-level similarity metrics and functional correctness. Additionally, we examine real-world deployment experiences and the infrastructural considerations for sustaining LLM-based review tools through continual instruction tuning. Our findings highlight a maturing field where diverse adaptation strategies and evaluation frameworks are converging, yet significant gaps remain in bridging the divide between automated metrics and practical code quality.


# 2 Introduction

The automation of software engineering tasks has emerged as one of the most transformative applications of large language models, with automated code review standing at the forefront of this revolution. Code review represents a fundamental quality assurance practice in modern software development, serving as a critical gatekeeping mechanism that identifies defects, enforces coding standards, facilitates knowledge transfer among team members, and ultimately safeguards the reliability and maintainability of software systems. Despite its importance, traditional code review remains a predominantly manual process that consumes substantial developer time, introduces inconsistencies due to human factors such as fatigue and varying expertise levels, and often creates bottlenecks in continuous integration and deployment pipelines. The advent of large language models with sophisticated code understanding capabilities has opened unprecedented opportunities to automate various dimensions of the review process, from detecting subtle bugs and generating precise fixes to providing constructive, context-aware feedback on code quality and adherence to best practices. These models, trained on massive corpora encompassing both source code and natural language, demonstrate remarkable abilities to reason about program semantics, interpret coding conventions, and generate contextually appropriate responses, positioning them as powerful tools for addressing the long-standing challenges of code review automation.

However, the path toward effective and reliable automated code review is fraught with several fundamental challenges that the research community has yet to fully resolve. The prevailing paradigm of full fine-tuning for code review tasks, while demonstrating promising results, raises critical questions about computational efficiency and model specialization, particularly as the scale of language models continues to grow exponentially. Although parameter-efficient adaptation strategies have gained traction in other domains, their systematic application to code review remains largely underexplored, leaving open questions about whether such approaches can match or exceed the performance of fully fine-tuned models while reducing resource requirements. More critically, the evaluation of automated code review systems suffers from a profound methodological crisis: commonly used similarity-based metrics such as BLEU have been shown to correlate poorly, and in some cases inversely, with functional correctness, yet the field continues to lack standardized evaluation frameworks that adequately capture the multifaceted nature of code review quality, including semantic accuracy, actionability of feedback, and developer acceptance. The deployment of large language model-based code review tools in industrial settings introduces additional layers of complexity, encompassing challenges related to continuous model adaptation, rigorous quality assurance, seamless integration with existing development workflows, and the mitigation of catastrophic forgetting during sequential task learning. Furthermore, while multi-agent frameworks and sophisticated prompt engineering strategies have demonstrated considerable promise, the intersection of continual learning paradigms with code review automation remains almost entirely unexplored, leaving fundamental questions unanswered about how such systems can evolve alongside changing codebases, emerging programming patterns, and shifting organizational standards.

This survey makes two primary contributions to the field of automated code review, addressing both the technical landscape and the practical considerations essential for real-world adoption. First, we provide a comprehensive and structured taxonomy of techniques that have been applied to code review automation, systematically organizing the diverse approaches that characterize this rapidly evolving field. Our taxonomy spans three major categories: fine-tuning approaches that adapt pre-trained models such as CodeT5 and PLBART for sequence-to-sequence repair tasks, prompt engineering strategies that leverage carefully crafted instructions to elicit repair responses from large language models, and multi-agent architectures that distribute code review responsibilities across specialized agents engaged in iterative refinement loops. Within each category, we examine the underlying mechanisms, representative implementations, and documented strengths and limitations. We pay particular attention to the emerging trend toward parameter-efficient specialization, including role-specific fine-tuning within cooperative multi-agent frameworks, and we analyze how prompt-driven debugging enables iterative test-and-fix cycles that leverage conversational capabilities and error traceback analysis. By organizing these techniques into a coherent conceptual framework, we enable researchers and practitioners to navigate the design space of automated code review systems, understand the trade-offs inherent in different architectural choices, and identify promising directions for future investigation that bridge currently disconnected research threads.

Second, we conduct an in-depth analysis of evaluation practices and industrial deployment challenges, two areas that are critical for the practical adoption of automated code review but have received insufficient systematic attention in the literature. We critically examine the benchmarks and quality attributes used to assess code review systems, providing a detailed analysis of the fundamental limitations of surface-level textual similarity metrics and articulating the urgent need for evaluation frameworks that capture functional correctness, semantic equivalence, review actionability, and developer acceptance. Our analysis draws on documented evidence of the disconnect between traditional NLP metrics and actual code quality, highlighting how continued reliance on inadequate evaluation approaches threatens to misdirect both academic research and industrial investment. Furthermore, we present a detailed examination of industrial deployment through the lens of the RovoDev Code Reviewer at Atlassian, one of the few large-scale online evaluations available in the literature, analyzing its code resolution rates, post-generation quality filtering processes, and the broader implications for sustaining such systems in production environments. We also address the infrastructure considerations essential for long-term deployment, including continual instruction tuning approaches designed to mitigate catastrophic forgetting during sequential task adaptation. Through this analysis, we bridge the critical gap between academic research and industrial practice, providing actionable insights for organizations seeking to deploy automated code review tools while maintaining the quality and reliability standards that modern software development demands.

The aim of this survey is to provide researchers and practitioners with a comprehensive understanding of the current state of large language model-based code review automation, encompassing both the technical approaches that define the research frontier and the practical considerations that govern real-world deployment. The remainder of this paper is structured as follows. We begin by establishing the necessary background on code review processes and the architectural foundations of large language models that enable their application to software engineering tasks. We then present our taxonomy of techniques, organized into three major sections covering fine-tuning methods, prompt engineering strategies, and multi-agent frameworks, with each section examining representative approaches and their documented performance characteristics. Following this technical exposition, we examine evaluation methodologies in depth, including a critical analysis of existing benchmarks, quality attributes, and the fundamental limitations of current metrics. We subsequently address industrial deployment challenges, drawing on available case studies and infrastructure research to illuminate the practical realities of deploying automated code review at scale. Finally, we identify open problems and articulate promising research directions, concluding with a summary of key findings and actionable recommendations for future work that can advance the field toward robust, reliable, and widely adopted automated code review systems.


# 3 LLM Fine-Tuning and Multi-Agent Architectures for Code Review

## 3.1 Parameter-Efficient and Federated Fine-Tuning for Code Review

The application of fine-tuned models to code review tasks has shown promise for automating program repair. Paul et al. (2023) fine-tuned both PLBART and CodeT5 on a dataset of buggy code and associated review comments, finding that CodeT5 achieved slightly better performance in generating repaired code, which they attribute to its stronger natural and programming language comprehension capabilities. Their approach frames code review as a sequence-to-sequence task, where the model receives the buggy code and review context and predicts the corrected version.

While full fine-tuning of pre-trained models remains the dominant paradigm in this area, recent work points toward more specialized and potentially efficient adaptation strategies. Khanzadeh (2025) suggests that within multi-agent frameworks, individual agents could be fine-tuned on role-specific data—such as training a dedicated “bugfixing LLM” for debugging tasks—to improve efficiency by shortening reasoning paths and reducing redundant steps. Although this proposal does not directly address parameter-efficient techniques like adapters or low-rank adaptation, it reflects a broader trend toward targeted model specialization that aligns with the goals of parameter-efficient fine-tuning.

## 3.2 Prompt Engineering and Retrieval-Augmented Generation for Program Repair

Prompt engineering has opened a new avenue for automated program repair by leveraging large language models to generate fixes from carefully crafted natural-language instructions. Paul et al. (2023) describe this direction as one in which researchers develop clear and concise prompts to obtain coherent and relevant repair responses from models. Their work situates prompt engineering within a broader landscape that includes fine-tuning and highlights the need for diverse techniques to advance the state of the art in repairing buggy code. The conversational program synthesis approach of CodeGen, which accepts multi-turn natural-language specifications, and the strong natural-language understanding demonstrated by GPT-3 are noted as representative capabilities that underpin such prompt-based repair strategies (Paul et al., 2023).

In multi-agent frameworks, prompt-driven debugging takes the form of an iterative test-and-fix loop. Khanzadeh (2025) presents a Debugger agent that uses an LLM to analyze a failure—for example, by reading an error traceback or identifying a logical mistake—and then proposes a fix. The agent subsequently applies the fix by generating a patch or revised code, repeating the process until the code meets the acceptance criteria of the subtask.

## 3.3 Multi-Agent Architectures and Iterative Refinement for Code Review

The integration of code review into automated software engineering tasks has been explored as a means to improve output quality. Paul et al. (2023) note that prior work has established that incorporating code review suggestions can enhance the quality of bug fix suggestions in automated program repair. They reference Tufano et al., who demonstrated this by comparing two transformer models: one that used only the buggy source code as input, and a second that used both the buggy code and the associated code review (Paul et al., 2023). This suggests that review information provides a valuable signal for refinement.

In multi-agent frameworks, the review process is often formalized as a distinct phase handled by a dedicated agent. Khanzadeh (2025) describes a cooperative multi-agent architecture where a Reviewer agent inspects the final aggregated codebase and outputs feedback or approval. This design incorporates a unidirectional flow of information with occasional feedback loops for debugging, and agents primarily communicate through artifacts such as plans and code (Khanzadeh, 2025). Such an architecture enables iterative refinement by explicitly separating code generation from code inspection.

# 4 Benchmarks and Evaluation Metrics for LLM-Based Code Generation

## 4.1 Benchmarks and Quality Attributes for Code Generation

In their critical review of code generation evaluation, Paul et al. (2024) structure the assessment landscape around two complementary pillars: the benchmarks used to test models and the quality attributes those benchmarks are designed to measure. The review devotes Section III to a survey of benchmarks employed in code generation evaluations, while Section IV focuses on the quality attributes and their associated metrics. This separation reflects a broader recognition that benchmark selection and the dimensions of code quality being assessed are deeply intertwined, and that a systematic understanding of both is necessary for meaningful evaluation. The review further dedicates Section IV-D specifically to performance metrics, indicating that computational efficiency and related measures constitute a distinct quality attribute category that warrants separate treatment (Paul et al., 2024). Finally, Paul et al. (2024) identify problems in current evaluation approaches, suggesting that existing benchmarks and quality frameworks may not yet fully capture the multifaceted nature of code generation quality.

## 4.2 Performance Metrics and Limitations in Code Generation Evaluation

A central limitation in code generation evaluation concerns the validity of commonly used performance metrics. Paul et al. (2024) observe that while similarity-based metrics have been a standard approach in machine learning research, their appropriateness for code generation has been questioned. Specifically, they note that Kulal et al. (2019) found that BLEU fails to assess functional correctness, and Hendrycks et al. (2021) further demonstrated an inverse relationship between BLEU scores and functional correctness (Paul et al., 2024). These findings underscore a fundamental disconnect between surface-level textual similarity and the actual executability or semantic accuracy of generated code, challenging the reliability of traditional NLP metrics in this domain.

# 5 Industrial Deployment and Self-Evolving LLMs in Code Review

## 5.1 Large-Scale Online Evaluation of LLM-Based Code Review in Industrial Deployment

While LLM-based code review automation is an active area of research, its evaluation in real-world industrial settings remains limited (Pornprasit & Tantithamthavorn, 2024). One notable exception is the deployment of RovoDev Code Reviewer at Atlassian, which provides a rare large-scale online evaluation. During a recent one-week period in July 2025, the system achieved a code resolution rate of 38.70% for its generated comments, compared to human-written comments (Pornprasit & Tantithamthavorn, 2024). The evaluation also tracked post-generation quality checks, showing that after this filtering stage, the proportion of human-authored comments (HAC) and pull request human-authored comments (PR_HAC) shifted substantially, indicating a refinement process that influences which comments ultimately reach developers (Pornprasit & Tantithamthavorn, 2024).

Broader challenges of deploying LLMs continuously in industry are addressed by Kang et al. (2025), who propose MoE-CL, a method designed to mitigate catastrophic forgetting during continual instruction tuning. By allocating a dedicated LoRA expert to each task, MoE-CL prevents new training from overwriting prior parameters and enables useful knowledge transfer through an adversarial LoRA expert architecture (Kang et al., 2025). While this work does not directly evaluate code review, it highlights the infrastructure considerations essential for sustaining LLM-based tools like RovoDev Code Reviewer in evolving industrial environments.

## 5.2 Self-Evolving LLMs via Continual Instruction Tuning for Code Review

Code review automation has become an active research area, with large language models (LLMs) increasingly applied to tasks such as reviewer recommendation, code review prioritization, and comment generation (Pornprasit & Tantithamthavorn, 2024). Fine-tuning LLMs on task-specific data has been shown to yield the best effectiveness for generating code review comments, and recent work has explored both off-the-shelf and fine-tuned models for this purpose (Pornprasit & Tantithamthavorn, 2024). However, the evidence provided does not describe any specific system or study that combines continual instruction tuning with code review.

Continual instruction tuning, as a general paradigm, refers to dynamically adapting LLMs through sequential task-specific instruction tuning, enabling them to incrementally incorporate new knowledge from evolving instructions while retaining performance on previously learned tasks (Kang et al., 2025). This approach is designed to support adaptation to diverse, changing task demands over time. Although the concept is relevant to domains where requirements and codebases evolve, the available source material does not establish a direct connection between continual instruction tuning and code review automation, nor does it present empirical results for self-evolving LLMs applied to code review. Consequently, while the two research threads—LLM-based code review and continual instruction tuning—exist in parallel, their intersection remains unexplored in the provided evidence.

# 6 Future Directions

The current landscape of automated code review and program repair is marked by several persistent limitations that hinder both research progress and practical adoption. Full fine-tuning remains the dominant adaptation strategy despite its substantial computational cost and the growing availability of parameter-efficient alternatives whose applicability to code review tasks has not been systematically evaluated. Multi-agent architectures and prompt engineering approaches, while promising, rely on heuristic design choices without rigorous comparative frameworks or theoretical grounding to guide agent orchestration and prompt construction. The evaluation crisis is particularly acute: surface-level similarity metrics such as BLEU have been shown to correlate inversely with functional correctness, yet the field lacks standardized benchmarks that prioritize executability, semantic equivalence, and developer acceptance. Industrial deployments remain scarce, and the few existing large-scale evaluations provide only preliminary snapshots of effectiveness without addressing long-term model maintenance or adaptation. Critically, the intersection of continual learning paradigms with code review automation remains entirely unexplored, leaving open the fundamental question of how review systems can evolve alongside changing codebases, programming practices, and organizational standards.

Future research should pursue three interconnected directions. First, a systematic comparative investigation of parameter-efficient fine-tuning strategies—including low-rank adaptation, adapter modules, and mixture-of-experts architectures—is needed to establish whether these techniques can match or exceed full fine-tuning performance for code review and repair tasks while reducing computational overhead. Such studies should examine generation quality across multiple programming languages, inference latency in deployment settings, and the ability to handle diverse review comment types, from style suggestions to logic corrections. Second, the community must develop fundamentally new evaluation frameworks that move decisively beyond text similarity. This requires constructing benchmarks centered on functional correctness through execution-based validation, designing human preference studies that capture developer trust and review actionability, and establishing longitudinal industrial metrics such as sustained comment resolution rates and defect prevention outcomes. Third, research should pioneer the integration of continual instruction tuning with code review systems, exploring rehearsal-based methods, architectural innovations for knowledge isolation, and online evaluation protocols that track model performance over extended deployment periods. This includes investigating how self-evolving review models can incrementally absorb new code patterns, domain-specific conventions, and evolving review standards without catastrophic forgetting of previously acquired capabilities.

Advancing these directions would yield transformative benefits for both research and practice. Parameter-efficient fine-tuning could democratize access to specialized code review automation, enabling organizations with limited computational resources to deploy effective tools and fostering broader participation in model development. Robust, functionally grounded evaluation frameworks would provide the research community with reliable instruments for measuring genuine progress, eliminating the risk of chasing misleading metrics and accelerating the translation of academic advances into industrial settings. Most significantly, the development of self-evolving code review systems represents a paradigm shift toward autonomous software engineering assistants that improve alongside the projects they serve. Such systems could progressively reduce the manual burden of code review while maintaining and even enhancing the quality and safety standards that modern software development demands, ultimately transforming code review from a development bottleneck into an intelligent, adaptive, and continuously improving process.


# 7 Conclusion

The automation of code review and program repair has undergone significant transformation, driven by the increasing sophistication of large language models and the diversification of adaptation strategies. This survey has examined the dominant paradigm of full fine-tuning, wherein models such as CodeT5 and PLBART are trained on sequence-to-sequence tasks to generate repaired code from buggy inputs and review context. The analysis reveals that while these approaches demonstrate promising capabilities, the field is progressively shifting toward more modular and specialized architectures. Multi-agent frameworks have emerged as a compelling alternative, introducing dedicated agents for debugging, reviewing, and code generation that collaborate through structured workflows and artifact-based communication. This architectural evolution reflects a deeper recognition that effective code review automation benefits from the explicit separation of concerns, enabling iterative refinement loops that more closely mirror human review processes. Concurrently, the survey has documented a critical methodological challenge that pervades the evaluation landscape: the fundamental disconnect between surface-level similarity metrics and functional correctness. The documented inverse relationship between BLEU scores and actual code executability underscores the inadequacy of traditional natural language processing metrics for assessing generated code quality, revealing an evaluation crisis that threatens to misdirect both academic inquiry and industrial adoption.

The significance of this survey resides in its systematic integration of research trajectories that have typically been examined in isolation. By juxtaposing fine-tuning methodologies, prompt-driven and agent-based architectures, and evaluation frameworks, the survey illuminates the complex interdependencies that define the current state of automated code review. The identification of emerging trends toward parameter-efficient specialization, including role-specific fine-tuning within multi-agent systems, points toward a future in which models can be tailored to distinct code review subtasks without incurring the computational burden of full retraining. Equally consequential is the survey's critical examination of industrial deployment experiences, which reveals both the early viability of large-scale systems such as the RovoDev Code Reviewer and the substantial infrastructure challenges associated with sustaining such tools in production environments. The analysis of continual instruction tuning paradigms, while acknowledging that their intersection with code review remains largely unexplored, highlights the pressing need for models capable of adapting to evolving codebases and review standards without catastrophic forgetting. By synthesizing these diverse threads, this survey equips researchers and practitioners with a structured understanding of both the achievements and the unresolved tensions that characterize the field, while providing actionable insights for organizations seeking to deploy automated code review tools.

The path forward demands concerted effort across multiple fronts. The research community must prioritize the development of robust evaluation benchmarks that transcend surface-level textual comparisons to capture the multifaceted nature of code quality, incorporating execution-based validation, semantic equivalence assessment, and developer acceptance metrics. The integration of continual learning paradigms with code review automation represents a largely uncharted frontier that warrants systematic investigation, particularly as industrial deployments demand models that can evolve alongside the projects they serve. Furthermore, the promising results from multi-agent architectures suggest that future work should explore more sophisticated coordination mechanisms and bidirectional feedback loops that better approximate the collaborative dynamics of human code review. Bridging the persistent gap between academic research and industrial practice will require not only technical innovations but also longitudinal studies that rigorously assess the long-term effectiveness, maintainability, and developer trust associated with automated review systems in production settings. The convergence of these research directions holds the potential to transform code review from a perennial bottleneck in the software development lifecycle into an intelligent, adaptive, and reliable automated process that enhances both productivity and code quality.
